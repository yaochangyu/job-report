# push-deploy 計畫書

## 目標

將目前已補跑到 `2026-05-25` 的資料整理後推送到遠端 `v1-3`，並部署到 GitHub Pages `v1-3` 版本目錄。

## 步驟

- [x] **步驟 1 — 檢查並整理要推送的工作樹**
  - 這一步需要先確認目前未提交的變更是否都屬於這次補跑與部署範圍，避免把無關檔案一起推上去。
  - 若需要 commit，這一步也會決定要納入哪些檔案，作為後續 push 的基礎。

- [x] **步驟 2 — 提交並推送 `v1-3`**
  - 這一步需要把步驟 1 確認過的內容提交到本機 branch，並推送到 `origin/v1-3`，讓遠端 branch 與本機一致。
  - 若不先完成這一步，部署完成後 repo 歷史仍會落後，後續追查資料補跑來源會不完整。

- [x] **步驟 3 — 部署 GitHub Pages**
  - 這一步會使用既有 `output/` 內容部署到 GitHub Pages 的 `v1-3` 目錄，讓站台可直接看到補跑後的最新資料。
  - 因為前一步已完成補跑與前端輸出，這裡可優先採用 `--skip-build`，避免重跑一遍資料流程。

- [x] **步驟 4 — 確認部署結果**
  - 這一步需要確認 `gh-pages` 已推送完成，且部署網址可對應到 `v1-3` 路徑。
  - 先做確認可以避免以為已上線，但實際上只有本機 output 更新。
