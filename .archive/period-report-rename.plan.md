# period-report-rename 計畫書

## 目標

將目前以 `monthly-report` 命名的功能，統一調整為較符合實際範圍的「週期報表 / period-report」，避免 UI 顯示與 URL 語意不一致，並保留舊連結的相容性。

## 實作步驟

- [x] **Step 1：盤點並統一路由 / view mode 命名**
  - 將 `monthly-report` 相關入口盤點清楚，包含 `view` query、`view_mode`、輸出路徑與前端 renderer 入口。
  - 先確認這些命名實際分散在哪些檔案，才能避免只改一半，造成 sidebar、URL、實際頁面行為不同步。
  - 這一步的目的是先把命名邊界定義清楚，降低後續改名時遺漏欄位的風險。

- [x] **Step 2：調整 UI 文案與主要命名為週期報表 / period-report**
  - 將使用者可見文案從「月報表 / Monthly Report」改為「週期報表 / Period Report」。
  - 同步把主要識別命名從 `monthly-report` 改為 `period-report`，包含 sidebar、`VIEW_META`、`view_mode`、輸出頁面路徑與相關設定。
  - 這一步是核心變更，目的在於讓功能名稱、網址語意與實際支援的月 / 季 / 年範圍一致。

- [x] **Step 3：保留舊網址相容與自動正規化**
  - 保留 `view=monthly-report` 與舊路徑的相容處理，讓既有書籤或外部分享連結不會立即失效。
  - 進入後可視需要自動轉成 `view=period-report`，讓新舊命名在一段過渡期內都可使用。
  - 這一步的目的是降低改名對既有使用者與已部署連結的衝擊。

- [x] **Step 4：更新文件與產出設定**
  - 更新 README、導覽描述與產出設定，確保文件、頁面標題、部署後路徑說明都與新命名一致。
  - 若有固定產出位置或站內導引，也要一併調整，避免文件仍引用舊網址。
  - 這一步可避免實作完成後，專案文件與實際行為不一致。

- [x] **Step 5：build 並確認週期報表入口可正常運作**
  - 依專案既有流程重新 build，確認新命名下的入口可正常開啟，且月 / 季 / 年切換不受影響。
  - 同時確認舊網址相容行為是否符合預期，避免只改名稱卻讓既有連結失效。
  - 這一步是必要的收尾，確保這次調整不只是文字替換，而是完整可用的命名切換。
